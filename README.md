# binomen

Code-aware biological name resolution for agents, plus a severity-graded harness
for measuring whether an agent knows to look a name up at all.

Two artifacts. The second is the one that matters.

1. **An MCP server** exposing deterministic, provenance-carrying name-resolution
   tools in three cost tiers. No answer is generated by a model; every value is
   a lookup or a rule applied to versioned reference data.
2. **An evaluation harness** measuring agent behavior on a silent failure mode,
   scored with a severity-graded error taxonomy rather than plain accuracy.

```
stage 1  check_name           local, ~2 ms,  ~25 tokens   call on every name
stage 2  resolve_name & co.   local, ~50 ms, ~450 tokens  reached by escalation
stage 3  consult_authorities  network, ~1 s, variable     reached by escalation
```

Each stage returns `escalate`, `reason` and `next`. **The data decides the
policy, not the model** — an agent does not have to judge which names are risky.

Name-resolution libraries already exist and are good (§2). An MCP surface over
them is useful but not novel. Severity-graded measurement of *agent* behavior on
this failure mode is where the contribution is.

---

## 1. The problem

Biological names are not stable identifiers. They change, and they change for
good reasons — phylogenomic evidence reveals a genus is polyphyletic, a species
proves to be a later synonym of one described decades earlier, a governing
committee restructures an entire rank. The scientific record does not
retroactively update. It accumulates strata.

### A worked example of a silent failure

A researcher runs a meta-analysis of *Clostridioides difficile* recurrence rates.
They query PubMed for `"Clostridioides difficile"[tiab]` restricted to 1990–2000.

They get almost nothing.

Nothing is broken. The genus was erected in 2016; before that the organism was
*Clostridium difficile*, and before 1938 *Bacillus difficilis*, and for a few
months in 2016 *Peptoclostridium difficile*. Four names, one organism, and the
query matched one of them.

Consider what the pipeline does next. It does not raise. There is no exception,
no warning, no zero-division. A near-empty result set is returned, and a
near-empty result set looks exactly like a finding — "little was published on
recurrence in that decade." The conclusion is wrong, it is publishable, and
nothing in the data says so.

This is a **join failure**, and join failures are invisible by construction:

- A literature search on the current name misses everything under prior names.
- A database query returns zero rows rather than an error.
- A meta-analysis undercounts with no signal that it has.
- Two names for one taxon become two organisms; one name reused across time
  becomes one organism.

### This happens across the entire tree of life

| Group | Example | Note |
|---|---|---|
| Bacteria | *Clostridium difficile* → *Clostridioides difficile* (2016) | Genus reassignment on phylogenomic evidence |
| Bacteria | *Enterobacter aerogenes* → *Klebsiella aerogenes* (2017) | Clinically significant; both names in active use |
| Bacteria | *Lactobacillus* split into ~25 genera (2020) | One of the largest single reorganizations in bacterial nomenclature |
| Bacteria | *Firmicutes* → *Bacillota*, *Proteobacteria* → *Pseudomonadota* (2021) | Phylum names came under the Code; adoption is uneven and ongoing |
| Fungi | *Candida auris* → *Candidozyma auris* (2024) | **Contested** — critics argue the transfer rests on limited sampling |
| Fungi | "One fungus, one name" (2011 Melbourne Code) | Dual anamorph/teleomorph naming abolished wholesale |
| Fungi | *Pneumocystis carinii* → *P. jirovecii* for the human pathogen | *P. carinii* remains valid — for the rat pathogen |
| Viruses | ICTV binomial species rollout | Committee renaming on a published annual cycle |
| Plants | *Aster* → *Symphyotrichum* and other segregates | Genus narrowed, not renamed |
| Animals | Annual bird and fish splits and lumps | Competing checklist authorities |
| Genes | `SEPT2` → `SEPTIN2`, `MARCH1` → `MARCHF1` (HGNC 2020) | Renamed partly because spreadsheets coerced the symbols into dates |

> Every claim in this table should be verified against its primary source before
> being used as ground truth. See §6 on verification — the case set ships
> unverified on purpose.

### Why language models are specifically bad at this

- Training corpora span decades with no temporal weighting. Both names are well
  attested; the model has no principled reason to prefer the current one.
- It will assert an obsolete name as current, in fluent prose, with no hedge.
- It will not flag that a synonymy exists, or that one is disputed.
- Asked for a nomenclatural authority and year, it will produce a plausible one.
- It has no concept of *as of when*, which is the only frame in which a
  nomenclature question has a correct answer.

The model does not decline these questions. It answers them. The failure is
silent, which is what makes it worth measuring.

## 2. Prior art, and what is actually new here

Taxonomic name resolution is not a new problem and this project does not solve
it. Existing work, all of it more mature than this:

- **taxize** (R) — the standard toolkit for programmatic name resolution
- **TaxonKit / pytaxonkit** — fast NCBI taxdump manipulation
- **ETE3** — tree and taxonomy handling
- **Global Names** resolver family — large-scale name reconciliation
- **GBIF species matching API** — excellent fuzzy matching over a broad backbone
- **Catalogue of Life / ChecklistBank** — aggregation across ~170 sources
- **Open Tree of Life taxonomy** — synthesis across NCBI, GBIF, Index Fungorum, IRMNG, WoRMS
- **NCBI Taxonomy** itself — the synonym handling here is built directly on it

If you want to resolve a list of names, use one of those. They are better at it.

The contributions here are narrower:

1. **An MCP surface** making name resolution available to agents as
   deterministic, provenance-carrying, code-aware tools — with the tool contract
   designed so that disagreement between authorities survives the call.
2. **A severity-graded evaluation** of agent behavior on a silent-failure mode,
   including whether the agent chooses to check and whether it surfaces genuine
   disagreement.
3. **A characterization of how tool-description wording affects invocation rate**
   — three description variants ship, and the wording is treated as an
   experimental variable rather than a UX detail.

Point 1 is the easiest thing to overclaim, so to be explicit: the underlying
resolution is NCBI's and GBIF's work, not this project's.

## 3. The four-codes argument: why a single "current name" string is the wrong return type

"Is this the same organism?" is not one question. It is governed by separate
codes with genuinely different rules about priority, homonymy, authorship, and
what "valid" even means.

| Code | Scope | Distinguishing feature |
|---|---|---|
| **ICNP** | Prokaryotes | A name has no standing until validly published in IJSEM or on a Validation List. "Not validly published" is a first-class status, not an error |
| **ICNafp** | Algae, fungi, plants | Basionyms and parenthetical author citations encode change history *inside the name*. The parentheses in *Candidozyma auris* (Satoh & Makimura) Liu et al. are load-bearing |
| **ICZN** | Animals | Priority and homonymy rules differ; no equivalent of ICNafp "combination" status |
| **ICTV** | Viruses | Taxonomy is committee-assigned on an annual release cycle; ranks are created and abolished wholesale. The right provenance is an MSL number, not a year |

Three consequences, all of which shaped the API:

**Status vocabularies are not interchangeable.** "Invalid," "illegitimate," "not
validly published," and "unaccepted" are four different assertions in three
different codes. `binomen` normalizes to a common enum for branching **and always
returns the source's native term alongside it**. Flattening them would destroy
the only information that makes the status actionable.

**Homonymy across codes is legal.** ICNP and ICZN do not police each other, so
*Bacillus* is a bacterium and a stick insect. A resolver that picks one is
guessing. `resolve_name("Bacillus")` returns both, disambiguated.

**Some groups have no determinate code.** Protists are claimed by both ICZN and
ICNafp, and some are validly named under both. `binomen` returns
`code: "undetermined"` with an explanation rather than picking. That is a real
answer, not a failure.

Which is why `resolve_name` has **no top-level `current_name` field**. There is a
test asserting its absence. If such a field existed, every caller would read it
on the happy path, and every contested case would silently degrade to whichever
answer happened to sort first. Callers must look at `candidates`, which is a
list.

## 4. Tool surface

Ten tools in three stages. Every response carries provenance and the governing
code.

### Stage 1 — cheap enough to call on everything

| Tool | Cost | Returns |
|---|---|---|
| `check_name` | ~2 ms, ~25 tokens | `verdict` (stable / superseded / has_synonyms / homonym / contested / unknown), `code`, `escalate`, and when escalating, `reason` and `next` |

This is the design decision the rest of the surface hangs off. *"Call this
whenever an organism name appears"* is an unreasonable ask for a tool that costs
a second and a thousand tokens, and a reasonable one for a tool that costs two
milliseconds and usually answers *nothing to see here*. Invocation rate is the
dominant term — a resolver that is never called has no effect on any outcome —
so the entry point is built to make the ask credible.

The response for a stable name carries no `accepted_name` field, because **for a
stable name the accepted name is the input**. That is what makes it 25 tokens.

### Stage 2 — local, no network, predictable cost

| Tool | Input | Returns |
|---|---|---|
| `resolve_name` | name | Candidate accepted names (a **list**), status in the governing code's vocabulary, identifiers, rank, authority, change chain, `resolution_id` |
| `check_currency` | name, optional `as_of` | Whether the name was accepted at that date, or an explicit statement that the as-of question is unanswerable locally |
| `get_synonyms` | name | All names for the taxon, by synonymy type, with native class labels |
| `expand_query` | **resolution_id** | Search-term set across the naming history, abbreviated genus forms, ready boolean/PubMed query |
| `compare_names` | name A, name B | Same taxon or not; the nomenclatural reason they differ; the nearest shared rank |
| `get_lineage` | name | Lineage, with the source named and its limits stated |
| `list_reclassifications` | group, since year | Changes in a group, with a count of how many are undated |
| `list_authorities` | group | Which code governs, which authorities exist, which were consulted, and the full code descriptions |

### Stage 3 — network

| Tool | Answers what nothing local can |
|---|---|
| `consult_authorities` | ICNP validity (*validly published* is an LPSN question — NCBI returns names that never were, with no indication); *as-of* dates (taxdump records that names changed, not when); whether a synonymy is disputed and by whom |

### Design decisions worth arguing about

**Stage 2 makes no network calls, enforced by a test.** An earlier version mixed
a local lookup and four HTTP requests behind one tool, so latency depended on
which name you passed. That is a bad property for something an agent is told to
call freely.

**Provenance rides with the value, not in a header** — but is stated once per
source rather than duplicated per candidate. Candidates attribute by source name.

**`expand_query` is gated behind a `resolution_id`.** Not security —
instrumentation. Expansion without resolved identity is a list of remembered
names. The gate forces a multi-step episode and lets the harness observe whether
the agent resolved identity or jumped to an answer.

**Failures return instructions, not tracebacks.** An agent that receives a stack
trace concludes the tool is broken and falls back to parametric memory, which is
the outcome the tool exists to prevent. Every error path returns an actionable
message plus an explicit `do_not`.

**Unresolvable comparisons return `null`, not `false`.** `false` reads as
"different organisms," and asserting a difference we did not establish is a very
major error.

**We never invent an authority string or a year.** Where the year is unknown the
field is *absent* — not null-with-a-guess — and a warning says which authority
would be needed to fill it.

### Response budget

Measured on the fixture, before and after the three-stage split:

| query | before | after (stage 1 + stage 2) | cut |
|---|---|---|---|
| *Escherichia coli* | ~392 tokens | ~24 (stage 1 only) | **94%** |
| *Clostridium difficile* | ~1,013 tokens | ~465 | 54% |
| *Candida auris* | ~1,028 tokens | ~538 | 48% |

Most of the saving on the common case comes from three things: the ~300-character
paragraph explaining what ICNP is no longer ships on every response (it lives in
`list_authorities`), null fields are omitted rather than emitted, and responses
are not pretty-printed. `tests/test_stages.py` asserts these budgets, so a future
change that makes responses fat again fails the suite.

## 5. Data, versions, licensing, and rebuilding the index

### Tiered architecture

**Tier 1 — backbone.** NCBI Taxonomy `taxdump`. Public domain (US government
work). Covers all cellular life *and* viruses from one download, which is why
the cross-kingdom generalization is close to free: `merged.dmp` plus the synonym
classes in `names.dmp` deliver most of the target behavior across every kingdom.

**Tier 2 — cross-domain.** GBIF Backbone Taxonomy (CC BY 4.0), live with local
caching. Chosen over Catalogue of Life and Open Tree for its fuzzy matching,
because agents produce misspellings and truncations, and "not found" is the input
most likely to make a model fall back on memory.

**Tier 3 — code-specific authorities.** LPSN (ICNP), MycoBank / Index Fungorum
(ICNafp), ICTV MSL (viruses). Shipped as configured extension points. **Verify
terms of use before redistributing derived data** — several are freely queryable
but not freely redistributable, so `binomen` queries and cites rather than
shipping derived copies. Unconfigured authorities report themselves as *not
consulted* rather than degrading silently.

**Tier 4 — beyond organisms.** HGNC gene symbols. Same failure class, arguably
higher impact for bioinformatics, and a documented case where symbol drift
corrupted the published record.

**Curated overlay.** `src/binomen/data/contested.json` carries the two things
taxdump structurally cannot express: that a synonymy is *disputed*, and the year
and reference of the act. Every entry is marked `unverified` until a human checks
it against the primary source.

### Licensing summary

| Source | License | Redistributable |
|---|---|---|
| NCBI Taxonomy | Public domain | Yes |
| GBIF Backbone | CC BY 4.0 | Yes, with attribution |
| LPSN | DSMZ terms | **No** — query and cite |
| MycoBank / Index Fungorum | Site terms | **No** — query and cite |
| ICTV MSL | Open | Yes, cite the MSL number |
| HGNC | Free | Yes, cite genenames.org |

### Two index artifacts, and why they are separate

```
binomen-stage1.sqlite   small. Verdict table + per-code Bloom filters.
                        This is the one you have to install.

binomen.sqlite          full local backbone: names, nodes, merges, overlay.
                        Optional. Stage 1 degrades honestly without it.
```

Measured against `taxdump-2026-08-11` (2.93M taxa, 5.0M name rows): **stage 1 is
95.7 MB, stage 2 is 525 MB.** Worth recording honestly that the pre-build
estimate for stage 1 was ~30 MB and was wrong, and wrong in an instructive way —
903,701 names carry recorded nomenclatural history, several times the guess. The
five Bloom filters total **1.87 MB of the 95.7 MB**; the exact verdict table is
essentially all of it. The probabilistic structure is what makes "no record of
this name" *certain* rather than a guess, and that is worth keeping, but it is
not where the size went. The size win was deleting the lineage cache: ~2.5 GB
avoided, confirmed by `--audit` against the real archive.

**Stage 1 is exact where it matters and probabilistic only where it is safe.**
Every name with recorded nomenclatural history — synonym, merge, homonym,
dispute — lives in an exact table and gets an exact answer. The Bloom filters
only ever certify the *absence* of history, and Bloom filters have no false
negatives, so "we have no record of this name" is certain. A false positive
means saying *no change recorded* about a string that is not really a name: a
missed `unknown`, never an invented rename. There is a test asserting no name
with real history is ever placed in a filter.

One filter per governing code, so the code comes back for free.

### What was cut from the index, and why

An earlier build materialized each taxon's root-first lineage as JSON so code
detection could read it directly. Measured on the fixture it was **62% of the
index**, and at real NCBI lineage depth roughly **840 bytes per taxon** — on the
order of a gigabyte — to answer a question whose answer is one of six values. It
is now a single `code` column, assigned in one pass at build time, and
`get_lineage` walks parent pointers on demand.

Also dropped from the slim build:

| content | kept? | why |
|---|---|---|
| `scientific name`, `synonym`, `equivalent name`, `misspelling`, `misnomer` | yes | these are the answer |
| `authority` | yes | the author citation; otherwise it would be fabricated |
| `merged.dmp` | yes | the lumping record — highest-value file in the archive |
| `type material` | **no** | strain designations (ATCC 25922). Nobody asks whether a strain code is still current |
| `common name`, `blast name`, `acronym` | genus rank and above only | "human" is worth resolving; ten thousand strain vernaculars are not |
| uncultured / environmental / unclassified / `sp.` taxa | **no** | dominate NCBI's taxid count, never the subject of a nomenclature question |
| `nodes.dmp` columns 5–13 | no | GenBank plumbing |

`--full` keeps everything. `--audit` reports exactly what is in your downloaded
archive — rows and bytes per name class, and how much the slim build drops —
so these are measurements against your release rather than claims from ours.

### Install — for a biologist

**[docs/INSTALL.md](docs/INSTALL.md) is the page to send people.** It assumes no
terminal and covers first use, the permission prompt, what each verdict means,
and troubleshooting. The short version:

Download `binomen.mcpb` from
[the latest release](https://github.com/Nebraskinator/binomen/releases/latest)
and double-click it. Claude Desktop shows an install dialog; accept it and
restart. The name index (about 46 MB) downloads on first use and updates itself
every couple of weeks.

No Python, no terminal, no NCBI download. The extension is ~16 KB — it carries
the server and no data, so a bug fix does not make anyone re-download the index.

Requires Claude Desktop with Node 22.5+ bundled (verified on 1.28929.0, which
ships Node 24). Available tools: `check_name`, `resolve_name`, `get_synonyms`,
`expand_query`. Lineage, reclassification listings and live authority queries
are stage-2 and stage-3 features and live in the Python server below.

### Install — for a developer

```bash
python scripts/bootstrap.py
```

Creates a virtualenv, installs the package, fetches a prebuilt ~107 MB stage-1
index, registers the server with Claude Code, and verifies the chain end to end.
Roughly two minutes, no compiler, no taxdump download. Safe to re-run.

`--client desktop` registers with Claude Desktop instead, `--client none` skips
it, `--full-index` also installs the 525 MB stage-2 index, `--build-index`
builds from NCBI rather than fetching.

Neither index is committed. Freezing a copy in git would reintroduce exactly the
staleness this project exists to detect — prebuilt indexes are *release
artifacts*, stamped with the taxdump release they came from, and
`binomen-fetch-index --check-age` warns when yours is old.

## 6. The evaluation harness

### Environment framing

An episode: the agent receives a question, may call tools, commits to a final
answer, and the answer is scored against ground truth. Observation space is the
question plus tool returns; action space is tool calls plus the final answer;
reward is verifiable. This is a **reinforcement-learning environment with
verifiable rewards**, and the same loop would serve as a training environment,
not only an evaluation one.

### Error taxonomy

Adapted from severity grading in clinical antimicrobial susceptibility testing,
where reporting a resistant isolate as susceptible and omitting a comment are not
averaged together. Plain accuracy is the wrong instrument: it scores a silent
join failure and a missing citation identically.

| Class | Definition | Weight |
|---|---|---|
| **Very major** | Asserts two names are different taxa when they are the same, or the same when they are different | 10 |
| **Major** | Uses a superseded name as current without flagging it | 4 |
| **Minor** | Correct identification, missing provenance or date qualifier | 1 |
| **Abstention failure** | Answered from parametric memory when a tool was available and needed | tracked separately |
| **False confidence** | Gave a single answer where authorities genuinely disagree | tracked separately |

The last two are **measured but not folded into the severity score**, deliberately.
Abstention failure co-occurs with correct answers — averaging it in would hide
the behavior under study. False confidence only applies to contested cases,
where scoring it as a correctness failure would penalize the same event twice.

**The abstention row is the research question: does the agent know when to look
something up?** A model that guesses correctly without checking has not
succeeded. It has been lucky, and it will not be lucky at scale. The report
prints a "correct but unchecked" count for exactly this.

### Case set

127 cases (101 development, 26 held out) across eleven categories: control,
historic, recent, split, homonym, distractor, multi-hop, literature-linking,
cross-code, contested, and gene symbols.

Prompts are written the way a working scientist would type them, not as taxonomy
quizzes. This matters more than it sounds. *"What is the current name of
Clostridium difficile?"* announces itself as a nomenclature question and any
competent agent handles it carefully. *"I'm writing up a case of Clostridium
difficile colitis — what should I call the organism?"* does not announce itself,
and that is where the failure actually lives.

### Ground truth is unverified until proven otherwise

Every case ships `confidence: "unverified"`. **The runner refuses to produce
reportable numbers until verification has run.**

```bash
python eval/verify_cases.py --live --write
```

This checks each case against the configured authorities, confirms what it can
machine-confirm, and flags conflicts for a human to adjudicate. It never edits
ground truth to match the tool — that would make the eval circular. Predicates
like `states_unknown` cannot be machine-verified at all and stay flagged for a
human with the primary literature.

This is not bureaucracy. A benchmark whose ground truth was written from the same
parametric memory it evaluates measures nothing, and this project's entire thesis
is that confident unverified assertion is the failure mode. Applying the standard
to ourselves is the minimum.

### Conditions and reporting

```bash
python eval/runner.py --condition both --model claude-sonnet-5
python eval/report.py eval/runs/run-*.jsonl --out eval/runs/report.md
```

Every case runs in **three** conditions:

| condition | setup |
|---|---|
| `baseline` | model alone, no tools |
| `tools` | binomen server available |
| `instructed` | binomen available **and** the system prompt tells the agent to call `check_name` whenever an organism name appears |

`instructed` is **diagnostic and must not be reported as the result.** It exists
because of a hand measurement (§7): with tools merely available, neither tool
description variant caused invocation on a prompt framed as a summarization
task, and an instruction flipped it immediately. Reporting only baseline-vs-tools
would say "tools barely help" when the truth is "tools are ignored unless asked
for, and help once they are" — but reporting `instructed` as the headline would
be worse, because telling the agent when to check deletes the research question
and drives abstention failure to zero by construction. Use it to bound what the
tools are worth when invocation is not the bottleneck. The reported comparison
is baseline vs. tools.

Results are reported by category and by error class, with invocation and
abstention broken out **per condition**. `report.py` deliberately emits **no
single headline accuracy number**.

### Two loops, kept separate

- **Discovery, conversational.** Install in Claude Desktop, use it by hand, log
  every failure. Tool not invoked; invoked with wrong arguments; correct result
  misread in the summary. These become cases.
- **Measurement, programmatic.** Run the case set in batch. Never tune against
  the cases used for the reported result — `heldout.jsonl` is run once, at the
  end. If you look at held-out failures and change anything, the holdout is burned
  and you need a new one.

### Tool description wording as a variable — and a negative result

Invocation rate is not a UX detail. A resolver that is never called has no
effect on any outcome, so it is the dominant term.

**First measurement, by hand, n=1 prompt** (method and the rules that keep the
numbers meaning something: `docs/TESTING.md`). One prompt, held constant, one
variable at a time, fresh session each run, Claude Code / Sonnet 5:

> Summarize the current treatment guidelines for C. difficile infection.

| condition | `check_name` called? | did the answer name the genus? |
|---|---|---|
| `broad` descriptions | no | no — used "C. difficile" throughout |
| `imperative` descriptions | no | no — same dodge |
| `imperative` + an instruction in the client's context | **yes** | yes — named the current genus and both prior names |

The model gave its own reason: *"per project instructions I need to verify it
with binomen's check_name first."* It cited the instruction, not the tool
description.

**Tool-description wording did not move invocation on this prompt.** The
`imperative` variant is as strong as the channel allows — it states that
answering from memory is an error, that the failure is invisible, and that there
is no reason not to call. No effect. The model had classified the request as
summarization before tool descriptions entered into it.

Note what the two non-calling answers did: both wrote "C. difficile" throughout
and never once spelled out a genus. Not wrong — routed around the question. A
reader learns nothing about the organism having three names in the literature,
and a search built from that answer is silently incomplete. Which is the failure
in §1, reproduced live, with the tool installed and idle.

The uncomfortable implication: **invocation is a property of the client context,
not of the tool**, and the lever that works is not the one this project
controls.

**What this does not license.** The obvious move — ship an instruction telling
the agent to always call `check_name` — is a trap, and the harness must not
adopt it as a default. The research question is *does the agent know when to
look something up*. Instructing it when removes the question and replaces it
with compliance: abstention failure goes to zero by construction, invocation
goes to ~100%, and the benchmark reports a number it manufactured. A resolver
that is called because it was ordered to has not demonstrated judgment any more
than one that guessed correctly has demonstrated knowledge.

The `instructed` condition is therefore **diagnostic, not a recommendation**. It
measures the ceiling: what the tools are worth when invocation is not the
bottleneck. Read against `tools`, it separates two failure modes that plain
accuracy conflates — *the tool did not help* versus *the tool was never asked*.
The headline comparison remains baseline vs. tools. `instructed` is the third
column, never the reported one.

This is n=1 and Claude Code presents itself as a coding assistant, which biases
against reaching for a taxonomy tool — in an earlier run it said so explicitly.
Treat it as the hypothesis the `instructed` condition now measures properly.

Three variants ship, selected with `BINOMEN_DESCRIPTIONS`. They differ only in
wording; schemas and behavior are identical.

| variant | approach |
|---|---|
| `narrow` | Conventional: names the domain, describes the return value |
| `broad` | Names the **trigger condition** — "use this whenever an organism name or gene symbol appears," not "use this for taxonomy questions" |
| `imperative` | `broad`, plus an explicit statement that answering from memory is an error |

The hypothesis: `narrow` under-triggers because a model does not classify
*"summarize this paper about C. difficile"* as a taxonomy question. It classifies
it as a summarization question and never considers the tool. Run all three, report
invocation rate per variant, and record what changed.

## 8. What was tried and dropped

**A materialized lineage cache.** Stored root-first lineage per taxon as JSON so
code detection could read it without a tree walk. It was 62% of the index and
about 840 bytes per taxon at real depth — roughly a gigabyte — to answer a
six-way question. Replaced by one `code` column assigned in a single pass at
build time. This was the single largest thing wrong with the first version, and
it was invisible until the index was measured per table rather than in total.

**One tool with variable cost.** The original `resolve_name` did a local lookup
*and* queried up to four live authorities, so its latency and token cost
depended on which name you passed. It also meant the cheapest possible question
— "is this name fine?" — cost the same as the most expensive one. Split into
three stages with an explicit escalation contract.

**Returning the code description on every response.** A ~300-character paragraph
explaining ICNP, identical every time, on every call. On a "nothing has changed"
answer it was most of the response. Moved to `list_authorities`.

**A top-level `current_name` string.** The first API returned one. It made
contested cases invisible — a caller reading `current_name` on *Candida auris*
gets a confident single answer and never sees the dispute, which is precisely
the failure the project exists to measure. Removed, and there is now a test
asserting the field does not exist.

**Candidate status describing the input.** Initially `candidate.status` reported
the name class of the *queried* string, so resolving `Clostridium difficile`
returned a candidate `Clostridioides difficile` with status `synonym`. Read
naturally that says the current name is a synonym — exactly backwards. Split
into `input_status` and `candidate.status`.

**A single `valid: true/false` field.** Attempted early as a convenience.
Impossible to define across four codes without lying: ICNP validity is about
publication venue, ICNafp legitimacy is about rule compliance, and ICTV has no
analogue at all. Replaced by the normalized-enum-plus-native-term pair.

**Writing our own fuzzy matcher.** Levenshtein over the name index worked poorly
on exactly the inputs that matter — agent-generated names with authority strings
attached, or wrong infraspecific ranks. Delegated to GBIF, which does it better.

**Guessing the code for protists.** An early version defaulted ambiguous lineages
to ICZN. It was wrong often enough, and silently enough, to be worse than
`undetermined`.

**Mapping NCBI's `includes` class to synonymy.** `includes` means "unidentified
material filed under this taxon" — `Candida sp. JHS-2008`, `Clostridium sp.
HMSC19D05`. Treating it as synonymy put strain junk into `expand_query` output,
so the tool built to improve literature searches was quietly appending garbage
terms to them. It now has its own normalized status and never reaches a search
string.

**Fixing that badly enough to manufacture the error the project grades worst.**
The first version of the authority stripper had no rank gate, so
`Clostridioides difficile QCD-32g58` — a *strain* — was reduced to
`Clostridioides difficile` and given the species' lookup key. Every strain of
every species inherited its parent's key. *Escherichia coli* became a 277-way
homonym.

That is **false conflation**: distinct taxa sharing one identifier, which §6
grades as a *very major* error when an agent does it. The indexer was doing it
wholesale. It shipped past 9/9 canaries because the canary checked only that a
name was *findable*, not that it resolved to one organism — being findable is
not the same as being right, which is roughly the thesis of this project.

Fixed with five gates, the load-bearing one being rank: NCBI attaches author
citations at species rank and above, and below that a taxon carries a strain
designation, which looks similar and means something else. The canary now also
fails on a false homonym.

**Assuming NCBI stores bare binomials.** It does not. Prokaryote synonyms are
stored as complete nomenclatural citations:

```
Clostridium difficile (Hall and O'Toole 1935) Prevot 1938 (Approved Lists 1980)
```

Nobody types that, so the bare binomial matched nothing. Worse, once the name
*was* found, `expand_query` emitted the citation as a PubMed search term — a
query-expansion tool generating a silently empty search, which is the failure it
exists to prevent, committed by the tool that names it. The bare form is now
indexed as an additional key, search terms are stripped, and the verbatim string
is kept in `get_synonyms` where it is evidence rather than input.

**Treating NCBI's brackets as literal characters.** NCBI wraps a genus in square
brackets when the species is known to be misplaced in it: `[Clostridium]
difficile`, `[Ruminococcus] gnavus`. For some taxa that bracketed string is the
*only* synonym recorded — there is no plain `Clostridium difficile` row. Because
the normalizer kept the brackets, a user typing the plain binomial matched
nothing and got `verdict: unknown`.

That is the silent lookup miss, committed by the tool built to detect it, on its
own headline example. It survived 61 tests because the synthetic fixture used a
plain synonym; it took the first build against real taxdump to surface. Brackets
are now folded for lookup, the raw string is stored intact, and the annotation is
*reported* rather than discarded — a genus flagged as wrong is advance warning of
a rename, which is exactly the kind of signal this project should be surfacing.

The general lesson, recorded because it recurred immediately: **a fixture written
by the same person who wrote the parser tests the parser against its author's
assumptions, not against the data.** Two normalization bugs shipped this way, and
both passed the full suite. The fixture's name strings have been corrected against
`taxdump-2026-08-11`, and correcting them instantly failed a third test —
`expand_query` was emitting author citations as search terms. Three bugs, one
root cause: fiction in the test data.

Mitigations, in order of how much they help:

- `--extract-fixture` builds a fixture from **real archive rows** for the names in
  `tests/fixtures/seeds.txt`. Prefer it over hand-writing.
- The build runs **canary names** and fails rather than shipping an index that is
  quietly wrong — checking both that each resolves *and* that it resolves to a
  single taxon.
- Canary failures explain themselves by looking — the first version asserted
  "not present in the source archive at all" without checking the archive.

**Aggressive name normalization.** Folding subspecific rank markers merged
*Escherichia coli* with *E. coli* subsp. *coli* in the lookup index — manufacturing
the exact false conflation the package is meant to detect. Normalization is now
deliberately conservative: case, whitespace, accents, and a few orthographic
variants only.

## 9. Limitations

- **The overlay is small and hand-curated.** Twelve entries, all `unverified`.
  It covers the reference cases and nothing else. Everything it asserts about
  dates and disputes needs primary-source confirmation.
- **No dates from the backbone.** NCBI taxdump records that names changed, not
  when. `check_currency(as_of=...)` therefore returns "unanswerable" for most
  names rather than a date. This is honest but it is a real gap, and closing it
  means Tier 3 authorities for every group.
- **Tier 3 authorities ship unconfigured.** LPSN requires credentials, MycoBank
  requires an endpoint, ICTV requires a downloaded MSL. Out of the box you get
  NCBI plus GBIF, which cannot answer ICNP validity questions at all.
- **`list_reclassifications` is a lower bound**, not a complete record, and says
  so in every response.
- **Deterministic scoring is conservative.** `states_unknown` and
  `flags_disagreement` are graded on keyword evidence of hedging, which will
  under-credit well-written answers that hedge in unusual phrasing.
- **The gene branch uses a shape heuristic.** An abbreviated genus and a gene
  symbol are not reliably separable from the string alone; `binomen` only treats
  something as a gene when it matches the symbol shape *and* fails to resolve as
  an organism, and it says so in a warning.
- **NCBI Taxonomy is not a nomenclatural authority.** It is a pragmatic
  classification for organizing sequence data, and it is not a phylogenetic
  hypothesis. `get_lineage` says this in every response, but it bears repeating:
  for a nomenclatural question, the code-specific authority is the source that
  counts.
- **Stage 1 can bless a nonsense string.** A Bloom false positive on a name with
  no recorded history returns `stable` rather than `unknown`, at roughly the
  configured rate (default 0.1%, `--fp-rate` to change). It never invents a
  rename, and stage 2 catches it, but the wording of a `stable` verdict is
  deliberately "no change recorded" rather than "this is a valid name."
- **Index sizes are estimates until you build.** The sandbox this was developed
  in cannot reach NCBI, so the reduction factors are computed from the fixture
  and from the archive's structure. `binomen-build-index --audit` reports the
  real numbers from your download; treat anything here as provisional until you
  have run it.
- **The build refuses to ship a silently wrong index.** Nine canary names must
  resolve or the build fails and explains what it found instead. This is cheap
  insurance against exactly the class of bug that shipped once already.
- **No results yet.** §7 is a format, not a finding.
