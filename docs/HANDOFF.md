# binomen — state of play

Written to hand a fresh session enough to continue without re-deriving anything.

## What this is

Biological names are not stable identifiers. *Clostridium difficile* is now
*Clostridioides difficile*; *Enterobacter aerogenes* is now *Klebsiella
aerogenes*; *Lactobacillus* was split into ~25 genera in 2020. Both old and new
names are heavily attested in the literature, so a name being familiar is no
evidence it is current — and a literature search on the current name alone
silently misses decades of prior work, returning few results rather than an
error.

Two artifacts:

1. **An MCP server** giving agents deterministic, provenance-carrying name
   resolution. Nothing is generated by a model; every value is a lookup or a
   rule applied to versioned reference data.
2. **An evaluation harness** measuring whether an agent knows to *check* — a
   severity-graded error taxonomy, not plain accuracy.

## The one open blocker

**The extension does not attach under Claude Desktop's built-in Node.**

- Claude Desktop 1.28929.0 (MSIX packaged), built-in Node **24.18.0** → server
  starts, client sends `initialize`, no reply, client times out after 60 s.
- Settings → Extensions → **"Use Built-in Node.js for MCP" turned OFF** → system
  Node **24.11.1** → attaches immediately and works.

That workaround is not acceptable for the target user (bench biologists with no
terminal), so this is the thing to solve.

**Already ruled out**, each by direct test rather than reasoning:

- Not the server. `node scripts/try_node_server.js` on Windows answers
  `initialize` in 81 ms, lists tools, serves a tool call, and downloads and
  installs the real 46 MB index from the GitHub release.
- Not the index download. It is installed at `C:\Users\ruhe\AppData\Local\binomen`
  and the extension will now find it already present.
- Not blocking I/O. The first-run download used to start before stdin was read,
  and checksums used `readFileSync` on a 123 MB file. Both fixed; verified
  `initialize` answers in 22 ms with a slow 40 MB download running.
- Not `user_config`. The optional directory setting and its
  `${user_config.index_location}` substitution were removed in v0.2.1.
- Not extensions being disabled. A minimal Node probe extension installed and
  ran fine on the same build.
- Not `manifest_version` 0.4 / `server.type: "uv"` — that combination *is*
  rejected ("the preview failed"), which is why this ships as manifest 0.3 with
  `type: node`.

## Architecture, briefly

**Three indexes**, all built by `binomen-build-index` from one NCBI taxdump:

| file | size | consumer |
|---|---|---|
| `binomen.sqlite` | 526 MB | Python resolver, eval harness — full backbone |
| `binomen-stage1.sqlite` | 107 MB | Python `check_name` — verdicts + Bloom filters |
| `binomen-field.sqlite` | 123 MB (46 MB gz) | the Node extension — verdicts, synonyms, authorities |

**Three tool stages**, each returning `escalate` / `reason` / `next` so the data
decides the policy rather than the model:

```
check_name           local, ~2 ms, ~25 tokens   call on every organism mention
resolve_name & co.   local, ~50 ms, ~450 tokens reached by escalation
consult_authorities  network, ~1 s              reached by escalation
```

**Two implementations**, Python and Node, which must agree exactly about what a
name means. `scripts/emit_conformance.py` generates ground truth; the Node tests
replay it. This caught two silent divergences before either shipped (see below).

**Strain names are derived, not stored.** A strain is a binomial plus a
laboratory designation; only the binomial is governed by a code, and the
designation never changes. `Clostridium difficile 630` became `Clostridioides
difficile 630` with nothing published about strain 630. So `split_designation()`
peels the suffix, resolves the species, and reattaches it — complete coverage of
1.5 M strain taxa at zero bytes.

## Measured findings worth keeping

**Tool-description wording did not drive invocation.** One prompt held constant
("Summarize the current treatment guidelines for C. difficile infection"), fresh
session each run:

| condition | tool called? | named the genus? |
|---|---|---|
| `broad` descriptions | no | no — said "C. difficile" throughout |
| `imperative` descriptions | no | no |
| `imperative` + an instruction in CLAUDE.md | **yes** | yes |

The model attributed the decision to the instruction, not the description. n=1,
and Claude Code frames itself as a coding assistant, which biases against
reaching for a taxonomy tool — so treat it as the hypothesis the harness's
`instructed` condition now measures properly. That condition is **diagnostic
only** and must not be reported as the result: telling an agent when to check
deletes the research question and drives abstention failure to zero by
construction.

**Token budget.** `check_name` on a stable name is ~98 characters. Before the
staged split, the same question cost ~390 tokens. `tests/test_stages.py` asserts
these budgets.

## Bugs found, and how

Every one of these was found by running against real data or a real platform,
not by review. Recorded because the pattern is the project's own subject matter.

| bug | found by |
|---|---|
| Materialized lineage cache was 62% of the index (~2.5 GB at scale) to answer a six-way question | measuring per-table bytes |
| NCBI brackets a misplaced genus — `[Clostridium] difficile` — and the normalizer treated brackets as literal | first build against real taxdump |
| NCBI stores prokaryote synonyms as full citations, not bare binomials | canary check |
| `expand_query` emitted those citations as PubMed search terms | correcting the fixture |
| Strain designations read as author citations → *E. coli* became a 277-way homonym | real-rows fixture |
| `includes` name class mapped to synonymy → strain junk in search terms | reading live output |
| BLAKE2b-128 unimplementable in Node; switched both sides to SHA-256 | conformance fixture |
| Python integers do not wrap; masking to 64 bits in JS gave Bloom **false negatives** | conformance fixture |
| Unanchored `build/` in `.gitignore` excluded `src/binomen/build/` from the repo entirely | first CI run |
| `conftest.py` replaced the whole environment, dropping `PATH` on Windows | CI on Windows |
| Test called `python3`, which does not exist on Windows | first packaging attempt |
| Fixture piped through stdout, decoded as cp1252, corrupting `Rosa × damascena` | conformance test |

The fixture itself was the root cause of three of these: it was hand-written
from assumptions about NCBI rather than from NCBI. `--extract-fixture` now
builds it from real archive rows, and `tests/fixtures/PROVENANCE.txt` records
which release.

## Remaining work

1. **The built-in Node blocker** (above). Nothing ships to bench biologists
   until this is solved.
2. **Eval results.** Needs an API key (Claude Pro does not include API access;
   billing is separate at platform.claude.com). `eval/runner.py --condition all`
   reports token usage so a 3-case run sizes the full set. Ground truth is
   `unverified` and the runner refuses to produce reportable numbers until
   `eval/verify_cases.py` has run.
3. **Does the instruction generalize?** Re-run the other four discovery prompts
   with a CLAUDE.md in place; check it does not over-trigger on *Homo sapiens*.
4. **Stage 1 could drop strains too** — they are derivable there as well, ~17% of
   taxa.
5. **Contested overlay is 12 hand-written entries, all `unverified`.** Dates and
   disputes need primary-source confirmation before anything is reported.
